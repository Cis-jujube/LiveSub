# 英译中、术语与系统音频链路迭代 · 2026-10-02

本轮使用现有模型、依赖和本地音频，完成 GitHub 调研、代码修改、真实模型对照及自动检查。确认的收益是独立术语避免生成、持续英文样本减少模型调用耗时和译文等待。真实 ScreenCaptureKit 音频到字幕上屏的延迟仍未验证；普通整句单独翻译没有提速。

## 改动与取舍

- 未变化的术语文件复用已解析配置和编译后的匹配规则。文件设备、inode、大小、修改/变化时间共同决定重载，支持原子替换；无效配置保留最后有效版本，删除文件恢复默认配置。
- 英译中只有一个完整匹配词库条目的独立术语，可带单个句末标点时，直接恢复偏好译法。含其他词语、否定、多词条或省略号的文本继续由模型生成。方向、会话/代次、源文修订、输出上限及保护标记检查保持有效。该路径仍经过模型准备和提示词组装，并不改善冷启动、ASR 或已有任务排队。
- 软件领域选入七个 CNCF 词条：observability、container orchestration、service mesh、load balancer、event-driven architecture、idempotence、continuous delivery。仅选中软件领域时生效，自定义词条优先。来源、CC BY 4.0 署名与具体文件见 [调研记录](english-chinese-latency-research-2026-10-02.md)。
- 识别与翻译保持各自原有工作线程，由一个后端实例共享的锁串行调用模型，减少 PyTorch MPS 与 MLX 的 GPU 争用。锁由实际执行的同步调用持有；取消 asyncio 等待者不会提前释放。新连接继承同一个锁，等待旧连接超时后仍在执行的模型调用完成。
- ASR 只跳过新增内容全为数字零的重复预览。非零低音量样本仍可触发修订，所有 PCM 及时间范围均保留到定稿。每帧 RMS 只计算一次，既有阈值、800 ms 预览、500 ms 静音端点、12 s 上限及队列限制保持原值。

缩短术语提示词/压缩 JSON 的试验没有改善普通句子耗时，并出现较不自然的译法，已恢复原提示及编码格式。`distributed systems` 的保护标记令一条故障持续时间句变为“未通过，耗时”，因此没有选入该预设；保留原句作回归，最终输出恢复为“分布式系统故障持续了0.03秒，而不是0.3秒。”。

不复用补静音后的 ASR 预览来定稿。四组英文合成音频前缀检查有一组在补 640 ms 零样本后改变了金融短语，详见 [排除试验](asr-zero-suffix-2026-10-02.json)。定稿继续识别完整尾部音频。

## 文本模型对照

[60 条样本](translation-iteration-cases.json)包含 58 条英文及 2 条中文、原有 34 条术语回归、CNCF 新词与数字/否定句。使用同一已加载模型、同一 GPU 工作线程，旧/新路径交替执行三轮；使用合成术语配置，未读取用户词库。输入基线是迭代前保存的运行时代码，模型和基线文件哈希记录于 [完整结果](translation-iteration-20261002-results.json)。

| 范围 | 对照次数 | 旧路径中位数 | 新路径中位数 | 生成调用旧 → 新 |
| --- | ---: | ---: | ---: | ---: |
| 12 个独立术语 | 36 | 161.83 ms | 0.58 ms | 36 → 0 |
| 48 条普通句子 | 144 | 263.84 ms | 288.04 ms | 144 → 144 |
| 全部样本 | 180 | 249.87 ms | 255.07 ms | 180 → 144 |

全部样本累计请求耗时 45,583.35 → 41,593.87 ms，约减少 8.8%；整体中位数没有下降。新增术语保护会增加普通句子的提示开销，不应宣称词库让每句话都更快。指定词及数字形式检查为 168/180 → 177/180：新路径仍有一条认证语境句把 authentication token 混写为“认证token”，三轮均未符合偏好“令牌”。这些是有限的词面检查，不是通用准确率。

原有 34 条样本的 102 个旧/新输出完全一致；全部样本 150/180 输出一致，没有空输出或保护标记验证失败。人工检查新词样本中的数字、否定和故障含义，排除了前述语义回归；仍不能证明一般译文自然度或全部语境正确。

## 实时节奏的模型/会话检查

按 160 ms 帧实时输入相同合成 WAV，逐个进程串行运行旧/新路径，加载耗时从下表排除。最终正式代码的对照见 [原始汇总](live-iteration-20261002-results.json)。这些是模型及会话层数据，不包含 ScreenCaptureKit、SpeakerKit、WebSocket 传输或 SwiftUI 上屏。

| 样本/指标 | 旧路径 | 新路径 |
| --- | ---: | ---: |
| 42.9 s 持续英文：当前源文修订的译文等待中位数 | 509.09 ms | 422.46 ms |
| 同样本：ASR 调用累计墙钟耗时 | 34,091.57 ms | 24,187.56 ms |
| 同样本：翻译生成累计墙钟耗时 | 22,419.06 ms | 16,009.12 ms |
| 同样本：首条当前修订译文 | 1,870.46 ms | 1,830.30 ms |
| 同样本：停止至 idle | 1,626.92 ms | 1,548.47 ms |
| 10.0 s 英文：首条当前修订译文 | 1,807.33 ms | 1,759.49 ms |
| 同样本：停止至 idle | 1,606.03 ms | 2,172.84 ms |
| 10.4 s 中文：首条当前修订译文 | 1,634.11 ms | 1,635.55 ms |
| 同样本：当前修订译文等待中位数 | 364.96 ms | 383.03 ms |

持续英文的译文等待约减少 17.0%，两个模型各自累计调用耗时约减少 29.1% 和 28.6%；ASR 调用 48 → 43、生成调用 41 → 37。全部三个样本的最终源文与译文完全一致，共六段 final、396 帧全部接收，无拒帧、错误或重复 final。追赶策略可以略减少中间预览次数，定稿完整保留。

这些每种路径/样本只有一次正式对照，受模型内核启动、线程调度、温度与其他进程影响。旧路径模型调用相互重叠，累计墙钟耗时不能当成 GPU 利用率或能耗。此前另一轮持续英文的新路径停止等待为 2,033.35 ms；短英文尾句也慢约 0.57 s，中文等待略增。因此不承诺首译、停止尾句或反向翻译统一提速。

```bash

  --baseline-backend-root .build/latency-20261002/baseline/backend \
  --cases docs/translation-iteration-cases.json --rounds 3 \
  --output docs/translation-iteration-20261002-results.json
backend/.venv/bin/python -B script/benchmark_live_iteration.py \
  --audio .build/latency-round2-20260930/en-sustained.wav --language English \
  --output .build/latency-20261002/live-repeat-en.json
```

`benchmark_live_iteration.py` 是一次性进程，不启动监听服务。正式测量使用实际会话内的执行器锁；早期 asyncio 锁试验仅用于决定是否继续调查，没有作为生产实现或取消安全性验收。
