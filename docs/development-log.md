# LiveSub 开发与验证记录

> 本文件保存 2026-10-04 之前 README 中的全部迭代说明、测试数字与构建记录，正文未改动，仅把链接调整为相对 docs/ 目录。当前使用说明见仓库根目录的 [README](../README.md)。

## 原 README（2026-10-03）

LiveSub 是面向 Apple Silicon Mac 的本地实时双语字幕 App。它从麦克风或系统音频获取声音，用 Qwen3-ASR-1.7B 识别中英文，再由本地离线模型生成译文。新源码与独立原生预览包在系统语言包可用时优先使用 Apple 英译中翻译；中译英和备用路径使用 Qwen MLX。当前运行的正式包仍是此前的 Qwen 版本。主窗口将原文与译文按连续段落对齐，透明悬浮层可把字幕放在正在观看的内容上方；你也可以选择要翻译的说话人、组合领域词库，并手动复制或导出字幕。音频与模型推理留在本机，字幕默认只保存在当前会话的内存中。项目目前是个人使用的部分验收版本，真实多人说话识别、长时间原生采集和跨设备分发仍待验证。

## 系统离线翻译与通信优化第四轮 · 2026-10-03

经用户明确确认，已通过 macOS 设置安装英语（美国）与简体中文翻译语言包，实际 API 检查两种方向均为 `installed`。新增 app 管理的私有管道翻译进程，使用系统 `lowLatency` 模型、跳过指定词条翻译并检查词条数量；保留完整译文、修订身份和 256-token 输出预算。已修复管道暂时不可读／写被误判为失败的问题，原生英译中可用时预览间隔为 100 ms；Qwen 仍保持 750 ms 间隔，中文方向、缺少语言包或原生失败时使用本地 Qwen。

96 个输入的三轮完整路径测试中，174 次普通英译中句子的中位数 **21.16 ms**、P95 **34.60 ms**、最长 **48.49 ms**；72 次连续修订句最长 **60.94 ms**。独立词条另计，282 次英文请求均走原生路径，6 次中文对照走 Qwen，288 次词面与修订身份检查通过。这是有限样本，部分原生技术译文仍不够自然，不能据此声称通用翻译质量已验收。

持续音频、未采用原型、复现命令及独立预览包的验证状态见 [第四轮报告](native-translation-round4-2026-10-03.md)。当前译文等待从识别结果就绪开始计时，包含术语处理、通信与排队；系统音频采集到屏幕显示仍需原生实测。正式运行包尚未替换，旧包保留等待新版本验收。

## 模型执行与硬件优化第三轮 · 2026-10-03

已执行 BaseRT 隔离评测、CPU／GPU 提交与读取批量化、MLP 3-bit 混合精度实验，并测量主机调度边界。两种批量化原型的完整输出一致但更慢；3-bit 普通句子中位耗时有所改善，却把 3.5 小时错译成三小时零十分；BaseRT 普通英文 P95 仍为 313.14 ms，另有语义范围变化。因此本轮候选均未采用，**300 ms 完整译文目标仍未达到**。结果与逐例证据见 [第三轮报告](translation-hardware-round3-2026-10-03.md)。

第三轮结束时，Apple 原生 `lowLatency` 评测工具与术语保护输入已编译、准备完成，英／简中语言包当时尚未安装，仅验证了缺少语言包时不翻译、不下载的行为。原生翻译的后续安装和测量见第四轮；现有运行 App 与 Qwen 翻译实现未在第三轮替换。

## 普通句子与硬件优化第二轮 · 2026-10-03

完整译文的 greedy 生成路径省去逐 token 流式对象、词表 detokenizer 构建和 log-probability 归一化，保留原有 Qwen 权重、提示词、术语保护、256-token 输出预算及 EOS／KV 缓存规则。96 个公开／合成输入的三轮配对中，288 对输出全部一致；普通英文句子中位耗时为 **292.77 → 225.03 ms**，157/174 次低于 300 ms，但 P95 仍为 318.73 ms。

**持续音频尚未达到 300 ms 目标。** 最终重跑的完整当前译文等待中位数为 370.46 ms、P95 为 587.92 ms，且不包含原生系统音频采集与屏幕显示。整块编译、INT4 投影融合、显式 KV 编译解码和前次译文批量验证均完成测量；收益不足或出现语义问题的候选已移除。方法、失败证据、检查与独立预览包状态见 [第二轮报告](english-chinese-round2-2026-10-03.md)，硬件与来源见 [M5 / 编译研究](english-chinese-hardware-research-2026-10-02.md)。正式运行包尚未替换。

## 英译中与计算效率更新 · 2026-10-02

本轮缓存未变化的词库配置与匹配规则；完整匹配一个词库条目的独立英文术语（可带一个句末标点）直接返回固定中文译法，普通句子仍由模型翻译。软件领域新增七个校订的 CNCF 词条，包括可观测性、容器编排、服务网格、负载均衡器、事件驱动架构、幂等性和持续交付；自定义词条仍优先。词名来源、许可和候选实现见 [GitHub 调研](english-chinese-latency-research-2026-10-02.md)。

识别与翻译保留各自的工作线程，在同一后端内串行使用 GPU，减少 Qwen MPS 与 MLX 同时推理的争用；断开连接后尚未结束的模型调用仍保持 GPU 占用约束。纯数字静音不再触发重复识别预览，定稿继续保留并识别完整尾部音频。60 条有限文本的三轮对照中，独立术语请求中位数为 161.83 → 0.58 ms；这不包含识别、排队、模型冷启动或上屏，普通句子单独翻译没有提速。完整测量、停止尾句的代价及包状态见 [本轮迭代报告](english-chinese-iteration-2026-10-02.md)。真实系统音频到屏幕的延迟仍需原生验证。

## 说话人检测与选择

在主窗口点击「检测说话人」→「开始检测」。首次使用会下载并加载
[SpeakerKit](https://github.com/argmaxinc/argmax-oss-swift) 的本地 Core ML 模型；
音频和说话人特征只在本机处理。开始录音后，应用会把可辨认的声音依次标为
说话人 A–E。弹出框中可勾选一位或多位；「翻译所有人」恢复全部翻译。
未选中说话人的原文仍保留在主窗口，后续译文不再生成；复制或导出会保留
可辨认的说话人标签。每次最多标记五位，
建议先在一至两位说话人的场景使用。

检测需要先积累约两秒音频，之后按约 800 毫秒的新音频批次更新；模型运算还会
增加实际延迟。重叠讲话、很短的发言和相近声线可能无法稳定分配身份，
会显示为未归属说话人。选择只作用于后续翻译，不会补译之前跳过的片段。
该功能尚需在真实多人音频上验证身份稳定性、时延和队列负载。

启动新的识别会话时，上一份字幕会保留到后端进入可用的监听状态；若模型加载失败，仍可复制或导出上一份字幕。设置页显示当前使用的 Qwen3-ASR 模型；错误提示仅在音频权限确实被拒绝时提供系统设置入口。正式 App 包只包含运行时后端模块，R2T2 对比与模型下载脚本仍保留在源码目录供开发使用。

## 识别模型与领域词库更新 · 2026-09-27

在同机同音频的小样本对比中，Qwen3-ASR-1.7B 对中英技术／金融语句的关键术语保留最好，现作为本地识别主引擎。处理跟得上音频输入时，它每约 800 毫秒给出可修订预览，在停顿或 12 秒上限处定稿。测试含一段公开中文录音和四段合成语音，尚不足以证明其在所有真实麦克风场景中准确率最高；详细逐字结果与复现命令见 [识别对比](asr-model-comparison.md)。翻译设置现可多选 AI、软件科技、数据统计、金融、量化金融、区块链词库，或选“AI 研发”“AI + 金融”快速组合。旧版 AI／通用配置可读取，保存时写入新版格式。翻译候选的同机小样本检查见 [翻译对比](translation-candidate-comparison.md)；当前仍用原来的 Qwen 翻译器。

## 阅读界面更新 · 2026-09-26

## 此前功能与验证记录

本轮新增共享且持久保存的“仅译文”显示选项，并调整预览调度、复用完全相同请求的模型输出。三组有限 WAV IPC 样本的最终译文等待中位数分别降低约 16.1%、43.3%、22.6%；首条译文基本持平，技术 TTS 首译慢 32.30 ms，不能承诺通用延迟改善。整套 80 项后端及 Swift／IPC 检查、release 签名和未录音状态的原生切换／重开持久化检查已通过。方法、基线和结果见 [仅译文与延迟更新](translation-only-and-latency.md)。上一轮 AI／科技术语、自定义词条及上下文改动见 [段落与术语更新](terminology-and-paragraphs.md)，来源见 [调研记录](terminology-research.md)。下方既有验收数字保留为历史快照。

上一轮本地文本模型测试的指定词检查为 **10/34 → 33/34**：其中 28 条是开发回归、6 条是最后新增的有限检查，不能称为通用翻译准确率。热模型短文本请求中位耗时从 232.56 ms 增至 306.18 ms；仍有未保护的认证语境词语混用英文、个别句子不够自然的问题。完整结果与失败见 [模型基准说明](terminology-benchmark.md)。上一轮 `./script/test.sh` 通过时包含 65 项后端测试及 Swift／IPC 检查；补入两项 Unicode 回归后，后端完整重跑为 **67 passed**，该轮最后两项回归期间 Swift 未改。11 秒真实人声 WAV 的后端 IPC 回归也已通过；这些不代表原生音频采集验收通过。

**当前是部分验收完成的个人本地版本。** 此前版本的麦克风英译中、中译英均已观察到环境音配对字幕；早期短播公开 WAV 的识别内容未能与样本对应。2026-09-29 的正式包已在安静环境中通过短时系统音频测试：公开中文 WAV 两次播放均产生与参考语句主体一致的原文字幕，第二次多了一个语气词。中英两种方向的后端曾通过直接输入真实录音的测试；原生一般准确率、悬浮实际覆盖区点击穿透、全屏/多屏兼容、断网实测及完整字幕链路的 30 分钟持续正确性仍待验证，详见 [人工测试矩阵](manual-test-matrix.md)。

**正式后端连续测试已通过 1,804 秒（30 分 4 秒）。** 一个 WebSocket 会话按实时节奏重复 164 次公开英文录音，收到 656 个最终译文和 6,238 个字幕事件，未报告错误、重复 final、修订倒退或源译错配，尾句保留。后端采样 RSS 峰值为 4,979.45 MiB、起止增加 64.76 MiB；片段近似结束至最终事件接收的中位数为 958.55 ms、P95 为 1,217.92 ms。这是 **backend-only** 结果，不包含 macOS 采集、Swift UI 或悬浮层，也不是说话结束到屏幕显示的延迟。详见 [测试方法](soak-backend.md) 与 [原始报告](soak-backend.json)。

## 系统与一次性准备

- Apple Silicon Mac，部署目标为 macOS 15 或更新版本；实际只在本机 macOS 27.0 测试，未验证 macOS 15/26 兼容性。本机实测环境与限制见 [交付报告](delivery-report.md)。
- Xcode Command Line Tools、Swift、`uv`；本轮系统翻译 helper 编译需要 macOS 26.4 或更新 SDK，本机使用 SDK 27.0。当前个人版没有公证，也没有 App Store 签名。
- 预留至少约 12 GiB 可用空间，用于 Qwen3-ASR、Qwen 翻译模型、构建和独立 Python 环境。模型在 `~/Library/Application Support/LiveSub/models/`，不会进入 Git 或 `.app`。

在源码目录执行一次：

准备模型或替换 `dist/LiveSub.app` 前，请先退出正在运行的 LiveSub。若窗口中还有要保留的字幕，请先复制或导出；只做独立预览包可使用下方的 `--verify-preview`。

```bash
LIVESUB_SIGNING_IDENTITY="YOUR_40_HEX_CERTIFICATE_SHA1" ./script/setup_models.sh
```

脚本依次准备锁定的 Python 3.12 环境、校验并准备 Qwen3-ASR 与 Qwen 翻译模型、使用指定身份签名 `.app`，最后准备 App 专用 Python 环境。缺少签名身份时在模型准备前退出。识别权重约 4.7 GB，翻译权重约 2.3 GB。模型来源、固定修订和哈希见 [模型清单](model-manifest.md)。下载失败可以重跑脚本。首次准备需要网络；模型就绪后识别和翻译使用本地模型，正式断网实测仍待完成。

## 构建、打开与测试

```bash
# 将占位符替换为 security find-identity -v -p codesigning 显示的有效证书 SHA-1
export LIVESUB_SIGNING_IDENTITY="YOUR_40_HEX_CERTIFICATE_SHA1"
./script/build_and_run.sh --verify   # 构建、检查正式 .app 签名，不打开
./script/build_and_run.sh --verify-preview # 图标预览；输出到 dist/previews/，默认临时签名
./script/build_and_run.sh --verify-ui-preview # UI 预览，使用独立 Bundle ID
./script/build_and_run.sh --verify-qwen-preview # Qwen 预览标识；使用当前源码构建
./script/build_and_run.sh --run      # 构建并打开 App
./script/test.sh                     # 后端、Swift 逻辑、IPC 检查与构建
```

测试脚本使用锁定依赖，执行后端逻辑测试、Swift 可执行断言、真实本机握手和 debug 构建；它不会重新跑真实模型音频基准、采集权限或悬浮交互验收。release `.app` 打包和签名由 `--verify` 单独检查。正式包必须明确设置 `LIVESUB_SIGNING_IDENTITY` 为钥匙串中有效代码签名证书的 SHA-1；缺少证书时脚本在构建和替换旧包之前退出，不会退回临时签名。`--run` 也需要此身份。预览包分别使用 `local.jujube.livesub.preview.icon`、`.preview.ui` 和 `.preview.qwen`，旧的同标识预览包保留在原路径；预览版默认临时签名，不作为正式包权限验收依据。预览模式只隔离包身份，不切换识别模型。App 图标母图位于 `assets/app-icon/LiveSubIcon.png`；打包脚本生成多分辨率 `.icns` 并放入 `.app` 资源目录。

## 使用

1. 打开主窗口，选择“麦克风”或“系统音频”，以及 `English → 简体中文` 或 `中文 → English`。首次打开不会自动录音。
2. 点击“开始”。macOS 首次可能请求麦克风或屏幕与系统音频录制权限；必须在系统提示中由你授权，拒绝后可在系统设置中调整并重新打开 App。
3. 主窗口“字幕显示”可选“双语”或“仅译文”，菜单栏也可切换；主窗口与悬浮层同步，并记住选择。切换不会重启会话、清除原文或触发重新识别，复制和导出仍保留双语。双语模式左列是原文，右列是对应译文；仅译文模式使用整栏显示译文。新内容持续加入当前段落，两列共用滚动区域；原文修订与迟到译文会更新原段落。原文先到时右列显示“翻译中”，不会用旧版本译文冒充新译文。拖动列标题之间的分隔线调整宽度。手动滚动暂停自动跟随，点“回到实时”恢复。
4. 点击“显示悬浮字幕”后，双语文字显示在普通应用之上。默认背景透明、鼠标穿透；双语模式原文在上、译文在下，仅译文模式隐藏原文并缩小面板高度。译文尚未到达时显示“翻译中…”。关闭悬浮层不会停止识别或删除主窗口记录。
5. 主窗口“字幕外观”可将悬浮字幕字号设为 18–40 pt；字号会保存，面板高度随字号调整。“调整位置与宽度”开启拖动模式：拖动字幕区域移动、拖动右下角改变宽度，再点“完成调整”恢复鼠标穿透。可分别恢复默认字号与位置。菜单栏 LiveSub 图标也可调节字号、暂停/继续、停止、隐藏/显示悬浮层、调整或重置字幕位置、恢复主窗口。
6. “复制全部”复制当前会话；“导出”可手动保存 UTF-8 TXT 或 Markdown。字幕默认仅在内存中；新会话进入监听状态后才清除上一会话的窗口记录，启动失败时可继续复制或导出旧字幕。
7. 打开“设置…”自由勾选 AI、软件科技、数据统计、金融、量化金融、区块链领域，或从“快速组合”选择“AI 研发”“AI + 金融”；全部取消即通用翻译。添加自定义词条时选择“英 → 中”或“中 → 英”，填写原文和固定译法，点击“保存术语”。保存后从下一次翻译请求生效，已有译文保持不变；自定义词条优先于预设。

术语配置仅保存在本机 `~/Library/Application Support/LiveSub/terminology.json`，最多 100 条，每个原文／译法为 1–80 个字符。它影响翻译，不会修改 ASR 原文。选中的词语会进行局部保护；模型未正确保留保护标记时会明确显示翻译失败，不把无效标记作为译文。歧义匹配、未保护词语和整句自然度仍有模型限制，具体未通过样例见本轮验证记录。

切换音源或翻译方向会结束当前片段并开始新的会话代次，旧字幕保持原方向。系统音频使用 ScreenCaptureKit，不保存屏幕视频。受系统或媒体保护限制的声音可能无法获取。

## 开发结构

- `app/LiveSub/Audio`：麦克风与 ScreenCaptureKit 采集，转换为 16 kHz 单声道 PCM16。
- `app/LiveSub/Backend`：独立 Python 子进程、本机 Bearer WebSocket、单连接和有界发送。
- `backend/livesub`：Qwen3-ASR、本地翻译调度、会话和字幕版本控制；R2T2 适配器保留用于历史对比。
- `app/LiveSub/Subtitles`：共享字幕 Store、稳定段落投影、术语配置校验与本地保存。
- `app/LiveSub/App/TerminologySettingsView.swift`：领域与方向化自定义术语编辑器。
- `backend/livesub/translation/terminology.py`：可组合领域词库、本地配置重载、匹配与歧义处理。
- `app/LiveSub/Overlay`：非激活、透明、默认鼠标穿透的 AppKit 面板。
- `shared/protocol.md`：音频帧、状态和字幕事件契约。
