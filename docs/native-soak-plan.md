# 原生 App 30 分钟验收方案（尚未执行）

目标是验证当前签名 `dist/LiveSub.app` 的真实 macOS 音源→Swift 音频转换→本地后端→主窗口／悬浮字幕全链路。后端单独的 WebSocket soak 不能替代此测试。执行本方案不修改、重包或重签 App。

## 前置条件与短测试

1. 等待后端独立 soak 结束并确认其进程退出，避免争用 GPU。使用最新签名 App，先运行 `codesign --verify --deep --strict dist/LiveSub.app`。
2. 若系统音频仍在 `SCShareableContent` 返回 `-3801`，先通过正常系统设置 UI 为当前包完成有效授权；不使用 `tccutil`，不修改其他 App 权限。启动采集后实际出现来自公开 WAV 的字幕才算权限路径通过。
3. 公开英文样本沿用 `/tmp/livesub-whisper-jfk-en.wav`（11 秒），公开中文样本沿用 `/tmp/livesub-r2t2-upstream-test-cn.wav`（约 6.74 秒）。固定来源和提交见 [IPC 测试说明](ipc-smoke.md)。不得用私人会议、网页或室内对话作为留图内容。
4. 先做单次短测试，确认选定音源和中英方向产生配对字幕，再开始计时。低增益从 `0.03` 尝试；如果识别不到声音，应在正式测试前调整至可靠的最低值并记录。增益过低会把测试变成静音等待，不能记为连续识别通过。脚本仅设置 `afplay` 的播放增益，不修改系统音量。
5. 如系统音频授权可用，优先使用系统音频英译中。可以用耳机降低外放干扰，但应在计时前固定输出设备并验证该路由确实被捕获；不能假设静音或任何设备路由下仍能捕获有效声音。
6. 如系统音频仍不可用，只能另做“麦克风声学回录”验收：扬声器播放公开 WAV，麦克风实际采集。设备和距离保持固定、环境安静，避免其他人员讲话；低音量仍需先验证可识别。耳机直接播放通常不能被麦克风可靠拾取。此方案包含房间声学、回声和底噪影响，且不证明系统音频功能通过。若低干扰条件无法实现，不启动半小时外放，保留该项未验证。

## 运行命令

以下为后续执行命令，准备阶段只运行 `--dry-run`。使用项目已有 Python 环境，无新依赖。

```sh
backend/.venv/bin/python script/native_acceptance.py play \
  /tmp/livesub-whisper-jfk-en.wav --seconds 1800 --gain 0.03 --dry-run
```

正式开始：手动打开 App、选择音源和方向、开始并等待模型进入监听状态。确认只有该 App 的一个直属后端，记录两者 PID。不要在测试中重启 App、模型或重新开始会话。

```sh
pgrep -x LiveSub
# 将上一步真实 PID 填入；仅列出直属子进程，不输出环境变量或 token。
ps -ax -o pid=,ppid=,comm=

# 把两个 PID 换成已核对的值；输出路径必须尚不存在。
backend/.venv/bin/python script/native_acceptance.py monitor \
  --app dist/LiveSub.app --app-pid APP_PID --backend-pid BACKEND_PID \
  --seconds 1980 --interval 10 --output /tmp/livesub-native-metrics.jsonl
```

在另一个终端开始播放，并保存仅含 WAV 哈希、计划和完成次数的输出：

```sh
backend/.venv/bin/python script/native_acceptance.py play \
  /tmp/livesub-whisper-jfk-en.wav --seconds 1800 --gain 0.03 \
  > /tmp/livesub-native-playback.jsonl
```

英文样本将完整播放 164 次，输入总时长约 1804 秒；每次启动 `afplay` 可能引入微小间隙，因此真实墙钟耗时稍长。这是重复公开语料的持续运行测试，不是多样语音准确率评估。Ctrl+C 会中断播放或监测；不会关闭 LiveSub。中断测试不得标记为完整 30 分钟通过。

监测器只读取指定 PID 的 RSS、`ps %CPU` 和启动时间，检查 PID 重用，验证后台进程最初属于 App，开始／结束时验证签名及主二进制哈希。它不读取字幕、录音、剪贴板、网络 token 或私人窗口。两条原始进程均退出后会提前结束并记录时间，不能把提前崩溃当成正常退出。`ps %CPU` 是系统提供的进程指标，不是精确 GPU 使用率或固定 10 秒区间的 CPU 利用率。

## 人工检查时间表

字幕数量从主窗口底部的“X 个片段”读取，只保存数字。记录每次的实际时间、App/后端 PID、数量、操作结果与错误码；不导出私人音频字幕。以下时间从正式公开音频开始播放算起。

| 时间 | 操作与所需证据 |
| --- | --- |
| 0–1 分钟 | 记初始片段计数，确认原文／译文配对；显示悬浮字幕。保存一张仅含公开样本的主窗口和悬浮层截图，检查透明背景、上下两种语言、行数与裁剪。 |
| 5 分钟 | 记计数。开关悬浮显示两次，检查计数继续增长、App/后端 PID 均不变；此处仅切换显示，不暂停采集。 |
| 10 分钟 | 浏览器仅打开无隐私的测试页面，把悬浮层置于页面按钮／输入框／滚动区上方；在正常锁定状态点击、滚动、输入测试文本，确认底层控件收到操作且焦点不被悬浮抢走。截图不包含历史标签、账号或私人内容。 |
| 15 分钟 | 在编辑器的新空白未保存文档中重复点击、键入和滚动；确认普通窗口之上可见。记计数和进程资源。不要修改用户已有文档。 |
| 20 分钟 | 从菜单栏进入位置调整，拖动／改宽，完成锁定，再验证穿透；执行重置位置并记录结果。菜单打不开则记录未通过，不把源码定义当实测。 |
| 25 分钟 | 关闭主窗口，确认菜单栏和字幕采集仍继续；从菜单栏恢复主窗口，检查历史和计数、PID 不变。 |
| ≥30 分钟 | 等播放器完成整段公开音频后，记最终播放时长与片段数；按停止，等待尾句和译文收尾、idle，记录 stop→idle 秒数及历史是否保留。检查公开样本已知末句是否出现，不保存私人文本。 |
| 停止后 | 正常退出 App，监测器应观察两个原始 PID 退出；另用 `pgrep -x LiveSub` 与进程列表确认没有新的 LiveSub 后端残留。检查监测尾部签名有效、二进制未变。 |

如果公开语音仍连续播放但片段数长期不增长，先记录故障时间、状态和错误码；不得仅因进程存活就标为识别稳定。RSS 上升需要结合后端模型驻留和当前会话历史增长判断；单次曲线不证明泄漏。默认可把短测试稳定后 RSS、末 5 分钟 RSS、峰值、增长量一起报告，不预先编造通过阈值。

## 另行短验收

- 中文→英文麦克风：正式 soak 结束后单独做一次公开中文 WAV 的麦克风声学回录；需明确记录为原生采集，不能用现有后端 IPC 中文结果代替。播放命令可将样本换成中文 WAV 并用 `--seconds 6.74`，先 `--dry-run` 查看重复次数。
- 新会话旧字幕：会话 A 有字幕后隐藏悬浮、停止、开始会话 B，在 B 尚无新声音时显示悬浮，检查 A 的字幕不会重现。
- 错误停止：若遇到真实错误，按停止应恢复 idle 且保留历史；不为构造此错误修改权限、破坏模型或杀死不相关进程。
- 6 秒淡出应在播放结束／停止后的无新字幕阶段观察。Space、全屏和多显示器需独立具备测试环境；没有第二块屏幕时保持多屏未验证。
- 断网验收单独协调，当前方案不改变网络设置。
