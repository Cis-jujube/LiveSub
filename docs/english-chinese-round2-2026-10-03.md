# 英译中性能第二轮 · 2026-10-03

**持续音频的完整译文等待尚未达到 300 ms 目标。** 本轮保留的普通英文句子优化已有约 23% 中位耗时改善，但不能把离线短句结果当作系统音频的上屏延迟。最新持续音频重跑为 **370.46 ms 中位数、587.92 ms P95**；全部修订中只有 13/40 次低于 300 ms。

## 保留的实现

`backend/livesub/translation/prompt_cache.py` 为完整字符串翻译增加专用 greedy 生成路径：直接从 logits 选 token，收集 token IDs 后一次解码，省去本应用不消费的逐 token 流式对象、词表 detokenizer 构建和全词表 log-probability 归一化；小型 allocator 缓冲可跨请求复用，超过 256 MiB 时清理。保留原有模型、权重、提示词、术语保护、BOS/EOS 规则、256-token 完整输出预算、异步一步 lookahead、模型流同步、wired-memory 范围及提示词 KV 前缀复用。实际生成结束后裁掉输出与 lookahead KV，失败时重置缓存。

直接 argmax 与归一化后的 argmax 在数学上等价，但有限精度可能改变极近 logits 的平局。下述输出一致性来自测量，不是对任何模型和提示词的保证。更换模型、运行库或生成设置后仍需复核完整输出。

`backend/livesub/session.py` 新增可选的本地模型调用计时观察器，分别记录 executor 等待、GPU 所有权等待和真实执行。普通应用没有启用观察器，不分配计时记录或读取额外时钟。GPU 锁继续由实际同步 worker 持有；取消 asyncio 等待不会让尚未结束的模型调用提前释放锁。记录不包含音频或字幕文本。

## 普通句子配对结果

同一加载模型、同一 MLX worker 串行交替执行上一轮与本轮，两个模式各自持有提示词缓存，预热和模型加载不计时。96 个公开／合成输入执行三轮，得到 288 对完整输出。输入包含 58 个普通英文句子、2 个中文对照、24 个同片段修订和 12 个独立术语。每对只是相同输入的 before/after，不是两次独立样本。时间覆盖请求准备、完整译文返回和随后少量字面检查开销，排除 ASR、采集、IPC 和 UI。本次所有请求零错误；输出一致比较的是完整文本。

| 输入组 | 配对次数 | 上一轮中位数 → 本轮 | 本轮 P90 / P95 | 本轮最大值 | 本轮 <300 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 普通英文句子 | 174 | 292.77 → **225.03 ms** | 297.97 / 318.73 ms | 448.14 ms | 157/174，90.2% |
| 同片段英文修订 | 72 | 292.27 → **219.61 ms** | 424.68 / 549.42 ms | 576.13 ms | 48/72 |
| 独立术语命中 | 36 | 0.58 → 0.48 ms | 0.66 / 0.72 ms | 0.96 ms | 36/36 |

普通英文中位数下降约 23.1%，总耗时下降约 23.0%。**288/288 对完整输出一致**；两边各有 252 次模型生成。独立术语已经在上一轮直接返回词库译法，没有调用模型，不能用它们把普通句子的延迟平均值拉低。原始输入、逐条译文、token 数和尾部耗时见 [96 个用例](translation-round2-cases.json) 与 [三轮配对报告](translation-round2-20261003-results.json)。

字面词检查不能代表翻译准确率：有效译文 `3.5 minutes → 3分30秒` 未命中只接受 `3.5`、`三个半` 或 `三点五` 的谓词；另有认证语境沿用英文 `token` 的既有问题。两边相同的检查结果不能证明一般准确率提高，也不能将该时间表达判为错误。

## 持续音频与实际生成

同一 42.87 秒合成英文音频按实时节奏输入，160 ms 一帧，使用当前 ASR、字幕修订与翻译调度。计时从本机 session 首次发出某个原文修订，到完整且与该修订匹配的译文发出。它没有经过 ScreenCaptureKit、说话人检测、WebSocket 或 SwiftUI，不是说话结束到屏幕的实测。

| 重跑 | 完整当前译文中位数 | P95 | 最大值 | 首条当前译文（含首次 ASR） |
| --- | ---: | ---: | ---: | ---: |
| 上一轮源码重跑 | 393.07 ms | 636.87 ms | 658.89 ms | 1,759.15 ms |
| 本轮首次 greedy 测量 | 324.62 ms | 558.08 ms | 586.08 ms | 5,202.75 ms |
| Metal command-buffer 参数试验 | 350.32 ms | 571.30 ms | 633.71 ms | 1,837.48 ms |
| **最终保留版本重跑** | **370.46 ms** | **587.92 ms** | **669.39 ms** | **1,925.23 ms** |

这些运行的修订数量和运行状态有差异，不能当作严格配对速度比；完整保留全部运行，避免只选择最快一轮。最终重跑 268 帧全部接受、40 个原文修订均得到当前译文、4 个最终片段的原文和译文与上一轮重跑完全一致，未报告错误。正确性通过和延迟达标是两个独立字段；延迟目标仍未通过。初次运行的首次 ASR 约 3.91 秒也保留在原始报告中。

最终重跑的翻译执行中位数为 369.86 ms，GPU 所有权等待 P95 为 0.05 ms、executor 等待 P95 为 0.30 ms。37 次真正生成的中位数为 375.34 ms。真实 ASR 推理中位数为 554.98 ms、P95 为 946.28 ms；把大量只收音频的廉价 ASR push 一并平均会误导瓶颈判断。因此当前主要成本仍是完整模型推理，进一步调整队列不能解释为数百毫秒收益。全部测量见 [持续音频报告](live-round2-20261003-results.json)。

随后仅在 benchmark 启用 `torch.inference_mode()` 包裹 ASR transcribe：完整当前译文中位数为 351.73 ms、P95 为 593.94 ms，真实 ASR 中位数 538.13 ms。42 个修订均翻译，4 个 final 原文一致，一个译文的空格和措辞变化。修订／缓存历史不同，这不是严格成对的数值或质量证明；该探针没有达到 300 ms，未改变生产识别路径。完整差异保留在同一报告中。

## 硬件和编译实验

本机为 M5 Pro、16 GPU cores、48 GiB unified memory，使用既有 MLX 0.32.2／MLX-LM 0.29.1 与 Qwen3-4B-Instruct-2507 4-bit 权重。已核查 M5 Metal 优化、量化 matvec、图编译、PyTorch MPS 选项和运行库版本。MLX 已包含 M5 相关优化；预填充的矩阵加速宣传数字不能直接推导单 token decode 或完整翻译耗时。环境、原始出处和限制见 [硬件研究](english-chinese-hardware-research-2026-10-02.md)。

完整句子测量后，以下候选均未接入运行时：

- 整个 MLP 编译：英文句子中位收益约 0.27%，不足以证明有效改善。
- INT4 gate/up、QKV 投影融合：单层测试有收益，96 个完整请求未获得稳定提速。
- 显式 tensor KV 的编译 decoder：完整请求反而慢约 2%，输出一致。
- 前次译文的目标模型批量验证：修订组更快，但有一例改变语义范围；全部移除，保留失败证据。
- 更大的 Metal command buffer：持续音频未得到稳定收益，默认环境参数保持原样。
- allocator 清理上限 256 → 1,024 MiB：96 对完整输出一致，实际清理从 31 次变为零；英文总耗时和 P95 未改善，全用例总耗时差约 0.12%，保留 256 MiB。单模型交替时 allocator 全局共享，不称为两份独立常驻池的内存对照。
- PyTorch MPS 编译 ASR 编码器前馈子图：3 对完整原文一致，确实调用编译代码且无 eager fallback；热技术音频 810.78 → 818.92 ms，新形状分别增加 24 次 trace 和约 0.58–0.60 秒总耗时，未采用。编译仅限纯张量 FFN，未编译整个识别器或解码缓存。

逐项结果、代码快照、数值差异和独立缓存审查见 [编译实验记录](compiled-translation-experiments-2026-10-03.md)。实验文件留在 Git 忽略的研究目录，生产没有候选编译适配器、草稿选项或草稿缓存状态。

下一项候选是 BaseRT 0.2.6 原生引擎。官方归档、真实许可、权重转换条件、C ABI wrapper、磁盘／内存开销及 96 个完整用例的命令已准备，见 [隔离测试审批材料](basert-isolated-benchmark-proposal-2026-10-03.md)。它是新增运行时，按用户 AGENTS.md 的依赖审批规则等待明确批准；尚未执行引擎或转换。引擎许可允许内部本机评估，公开工具的 Apache-2.0 许可不覆盖引擎的第三方分发。测试批准不能自动扩展为正式集成或分发批准，性能也尚未验证。
